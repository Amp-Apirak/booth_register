# ระเบียบปฏิบัติงานเรื่องการควบคุมเอกสารและระบบข้อมูล (Document Control Procedure)
## รหัสเอกสาร: REG-QA-SOP-001 | เวอร์ชัน: 1.0 | วันที่ประกาศใช้: 30 สิงหาคม 2026

---

## 1. วัตถุประสงค์ (Purpose)
เพื่อรับประกันว่าเอกสาร ระบบออกแบบ และบันทึกข้อมูลทางเทคนิคทั้งหมดในโครงการ **Smart Event Registration** ได้รับการจัดทำ ตรวจสอบ อนุมัติ ปรับปรุง และแจกจ่ายอย่างเป็นระบบ สอดคล้องกับข้อกำหนดของมาตรฐานบริหารงานคุณภาพ (ISO 9002) เพื่อป้องกันการนำเอกสารที่ล้าสมัยมาใช้งานโดยไม่ตั้งใจ

## 2. ขอบเขต (Scope)
ระเบียบปฏิบัติงานนี้ครอบคลุมเอกสารทุกประเภทที่จัดทำขึ้นภายใต้โครงการนี้ ได้แก่:
1.  เอกสารข้อกำหนดความต้องการระบบ (Product Requirement Documents - PRD)
2.  สถาปัตยกรรมและสเปกการออกแบบ (System & Network Design Specification)
3.  เอกสารตัดสินใจเชิงโครงสร้าง (Architectural Decision Records - ADR)
4.  ตารางตรวจสอบย้อนกลับความต้องการ (Traceability Matrix)
5.  ซอร์สโค้ดและโครงสร้างฐานข้อมูล (Source Code & Database DDL)

## 3. การกำหนดรหัสและเวอร์ชันเอกสาร (Document Identification & Version Control)

### 3.1 การระบุรหัสเอกสารหลัก
เอกสารโครงการทุกฉบับต้องได้รับรหัสระบุพิกัดโดยใช้รูปแบบดังนี้:
`[ชื่อโครงการ]-[หมวดหมู่]-[ประเภทเอกสาร]-[ลำดับลำดับสามหลัก]`

*   **ชื่อโครงการ**: `REG` (Event Registration)
*   **หมวดหมู่**:
    *   `PM`: ฝั่งบริหารจัดการโครงการ (Project Management)
    *   `SA`: ฝั่งออกแบบสถาปัตยกรรมและวิเคราะห์ระบบ (Systems Analysis)
    *   `QA`: ฝั่งการควบคุมและตรวจสอบคุณภาพระบบ (Quality Assurance)
*   **ประเภทเอกสาร**:
    *   `SOP`: เอกสารระเบียบปฏิบัติงานมาตรฐาน (Standard Operating Procedure)
    *   `SPEC`: เอกสารข้อมูลทางเทคนิคเฉพาะ (Technical Specification)
    *   `REP`: รายงานผลการดำเนินงานและผลลัพธ์ (Report)

### 3.2 การนับรุ่นเอกสาร (Revision Control)
*   **ฉบับร่าง (Draft version)**: ให้ใช้ทศนิยมนำหน้า เช่น `0.1`, `0.2` ในช่วงระหว่างเตรียมการ
*   **ฉบับประกาศใช้จริง (Approved version)**: เริ่มต้นที่รุ่น `1.0` และการปรับปรุงระดับย่อยจะใช้ `1.1`, `1.2` (Minor Change) ส่วนการปรับปรุงใหญ่ที่เป็นนัยสำคัญเชิงสถาปัตยกรรมจะเริ่มที่รุ่น `2.0` (Major Change)

## 5. ขั้นตอนการทบทวนและอนุมัติเอกสาร (Review & Approval Pipeline)

1.  **การริเริ่มและการเขียน (Creation)**: จัดทำโดยโปรแกรมเมอร์ SA หรือผู้เขียนเอกสาร โดยกรอกเนื้อหาและอ้างอิงให้ครบถ้วนในเวอร์ชันร่าง `0.x`
2.  **การตรวจทาน (Review)**: ตรวจทานโดย Systems Analyst (SA) เพื่อความถูกต้องทางโครงสร้างและการทำงานทางเทคนิค
3.  **การอนุมัติใช้งาน (Approval)**: อนุมัติโดย Project Manager (PM) หรือผู้รับผิดชอบโครงการที่ได้รับมอบหมาย โดยทำการอัปเดตรุ่นเป็นเลขจำนวนเต็ม (เช่น `1.0`) และบันทึกประวัติลงในตารางประวัติการแก้ไข
4.  **การกระจายเอกสาร (Distribution)**: เอกสารที่ได้รับการอนุมัติแล้วจะถูกรวมเข้ากับ Git repository หลักในเครื่อง และถูกเผยแพร่ในโฟลเดอร์เอกสารกลาง `docs/` เพื่อให้ทุกคนดึงไปใช้แบบทิศทางเดียว
