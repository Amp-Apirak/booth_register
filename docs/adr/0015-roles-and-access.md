# 0015-roles-and-access

ทุก endpoint มีระดับสิทธิ์ 3 ระดับ ตรวจที่ server (`routes/api.js` + `requireRole` ใน `middlewares/authMiddleware.js`) และหน้าเว็บแสดงตามเดียวกัน (`components/StaffGate.tsx`, เมนูใน `Navigation.tsx`)

| ระดับ | ใคร | ทำอะไรได้ |
|---|---|---|
| สาธารณะ | ทุกคน | ลงทะเบียน, ค้นหาตั๋วของตัวเอง (รหัสตั๋ว + เบอร์โทร 4 ตัวท้าย หรืออีเมล), ดูตัวเลขสรุป/กำหนดการ/ของรางวัล/ประเภทองค์กร/รายชื่อผู้ได้รางวัล (จอ LED) |
| เจ้าหน้าที่ (Staff หรือ Admin) | login แล้ว | สแกนเช็คอิน, ดู/เพิ่ม/แก้ไขผู้เข้าร่วม, รายงานและกราฟ, สุ่มรางวัล |
| Admin เท่านั้น | role = Admin | ตั้งค่าระบบทุกแท็บ (ข้อมูลงาน, กำหนดการ, หน้าลงทะเบียน, ประเภทองค์กร, ของรางวัล), ลบผู้เข้าร่วม, นำเข้า Excel |

**เหตุผล:**
1. เดิม role มีในบัญชีแต่ไม่ถูกใช้ บัญชี Staff ทำได้ทุกอย่างเท่า Admin และ `POST /lucky-draw/spin` ไม่ต้อง login ใครก็สุ่มรางวัลได้
2. แบ่งตามงาน: Staff ทำงานวันงาน (จุดสแกน, หน้างาน) ได้ครบรวมเพิ่ม walk-in และแก้ข้อมูล แต่เปลี่ยนการตั้งค่า ลบ หรือนำเข้าทั้งไฟล์ไม่ได้
3. หน้า `/ticket` เดิมเรียก API ของเจ้าหน้าที่ ผู้เข้าร่วมที่ไม่ได้ login ถูกพาไปหน้า login จึงเพิ่ม `POST /tickets/lookup` ที่ต้องมีทั้งรหัสตั๋วและข้อมูลยืนยัน เพราะรหัสตั๋วเดาได้ ตอบแบบเดียวกันไม่ว่ารหัสหรือเบอร์ผิด ผิด 5 ครั้งต่อรหัสตั๋ว หรือ 30 ครั้งต่อเครื่อง ภายใน 15 นาที จะถูกพัก
4. login ผิด 10 ครั้งต่อ username+เครื่อง ภายใน 15 นาที จะถูกพัก 15 นาที (429 `TOO_MANY_ATTEMPTS`); หลัง reverse proxy ต้องตั้ง `TRUST_PROXY=1` ให้นับตามเครื่องผู้ใช้จริง (ตั้งไว้แล้วใน deploy)
5. หน้าเจ้าหน้าที่ที่เปิดโดยยังไม่ login แสดงปุ่ม "เข้าสู่ระบบเจ้าหน้าที่" แล้วกลับมาหน้าเดิม (`/login?next=`) แทนการเด้งไปหน้า login ทันที (ตัวเลือก A ที่เสนอเจ้าของระบบ)

**ผลกระทบ:**
- บัญชีเดิมที่เป็น Staff จะเข้าหน้าตั้งค่าไม่ได้แล้ว ถ้าต้องการให้ตั้งค่าได้ ให้ตั้ง role เป็น Admin: `node scripts/create-admin.js <username> '<รหัส>' Admin "<ชื่อ>"`
- endpoint ใหม่: กำหนดระดับใน `routes/api.js` (`staff` หรือ `admin`) และเพิ่มในรายการ `PROTECTED` ของ `server/tests/security.test.js`
- เช็คอินบันทึก `checkins.scanned_by` = บัญชีที่สแกน เพื่อตรวจย้อนหลัง
- ปรับสิทธิ์ภายหลังได้ที่ `requireRole(...)` ใน routes และ `access` ใน `Navigation.tsx` / `roles` ของ `StaffGate`
