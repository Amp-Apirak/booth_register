# 0017-backup-and-reset

เมื่อจบงาน เจ้าของระบบต้องการสำรองข้อมูลทุกหมวดเป็น Excel แล้วรีเซ็ตระบบกลับเป็นค่าเริ่มต้นเพื่อใช้กับงานถัดไป ระบบจึงมีปุ่ม "ส่งออก Excel" และ "รีเซ็ตเป็นค่าเริ่มต้น" ในทุกแท็บของหน้าตั้งค่า และมีแท็บใหม่ "สำรองและรีเซ็ต" (`/settings?tab=backup`) ที่ทำได้ทุกหมวดในที่เดียว

**หมวดที่รีเซ็ตได้ และค่าเริ่มต้น**

| หมวด | หลังรีเซ็ต |
|---|---|
| ข้อมูลทั่วไป | ชื่องานเป็น "SMART EVENT REGISTRATION" ช่องอื่นว่าง (โลโก้ สถานที่ วันเวลา ผู้ติดต่อ ลิงก์แผนที่ นโยบายความเป็นส่วนตัว) |
| หน้าลงทะเบียน | รูปแบนเนอร์ รูปโบรชัวร์ ข้อความแนะนำ วัตถุประสงค์ และเงื่อนไข ว่างทั้งหมด |
| ประเภทองค์กร | ลบทั้งหมด แล้วใส่รายการเริ่มต้น 6 รายการ (`DEFAULT_TYPES`) ผู้เข้าร่วมที่ยังอยู่จะแสดงเป็น "ไม่ระบุ" |
| กำหนดการ | ลบทั้งหมด |
| ของรางวัล | ลบทั้งหมด รายชื่อผู้ได้รางวัลยังอยู่ (เก็บชื่อรางวัลไว้ในตัวเอง) จนกว่าจะรีเซ็ตข้อมูลผู้เข้าร่วม |
| ข้อมูลผู้เข้าร่วม | ลบผู้ลงทะเบียน การเช็คอิน และผู้ได้รางวัล |
| ทั้งระบบ | ทุกหมวดข้างบนในครั้งเดียว |

บัญชีผู้ใช้ (Admin/Staff) ไม่ถูกลบในทุกกรณี

**เหตุผล:**
1. **Admin เท่านั้น** (`GET /events/:id/reset-summary`, `POST /events/:id/reset`) เพราะเป็นการลบข้อมูลถาวร
2. **ทุกปุ่มรีเซ็ตมีหน้าต่างยืนยัน** ที่บอกสิ่งที่จะถูกลบพร้อมจำนวนจริงจาก server มีปุ่ม "ส่งออก Excel ก่อน" ที่ดาวน์โหลดแล้วหน้าต่างยังเปิดอยู่ ปุ่มยืนยันสีแดงอยู่ขวาสุด และโฟกัสเริ่มที่ "ยกเลิก" ส่วนการรีเซ็ตที่ลบรายชื่อผู้เข้าร่วม (ข้อมูลส่วนบุคคล) และการรีเซ็ตทั้งระบบ ต้องพิมพ์คำว่า RESET ก่อน
3. **ทำใน transaction เดียว** (สำเร็จทั้งหมดหรือไม่เปลี่ยนเลย) และใช้ lock เดียวกับการสุ่มรางวัล จึงไม่มีการสุ่มแทรกกลางการรีเซ็ต server บันทึก log ชื่อผู้กดและจำนวนที่ลบ
4. **ข้อมูลผู้เข้าร่วมเป็นหมวดแยก** เพราะเจ้าของระบบระบุเฉพาะหมวดการตั้งค่า แต่การใช้กับงานถัดไปต้องล้างรายชื่อด้วย การรีเซ็ตทีละหมวดจึงล้างเฉพาะการตั้งค่าได้ ส่วน "รีเซ็ตทั้งระบบ" รวมรายชื่อด้วย
5. **Excel ของแต่ละหมวดใช้หัวคอลัมน์เดียวกับไฟล์นำเข้า** (กำหนดการ ของรางวัล ผู้เข้าร่วม) จึงนำกลับเข้าได้ ไฟล์สำรองรวม (`event-backup-วันที่-เวลา.xlsx`) มีชีตสรุป 1 ชีต ตามด้วย 1 ชีตต่อหมวด และชีตผู้ได้รางวัล ตัวสร้างไฟล์อยู่ที่เดียว (`client/src/lib/backupExport.ts`) ใช้ร่วมกันทั้งปุ่มในแต่ละแท็บ แดชบอร์ด และไฟล์รวม ข้อมูลอ่านใหม่จาก server ทุกครั้ง และถ้าส่วนใดโหลดไม่ได้จะไม่สร้างไฟล์เลย จึงไม่มีไฟล์สำรองที่ขาดข้อมูลแบบไม่รู้ตัว
6. **รูปภาพไม่อยู่ใน Excel** เพราะช่อง Excel เก็บได้ 32,767 ตัวอักษร แต่รูปเก็บเป็น data URL ที่ใหญ่กว่ามาก ไฟล์จึงเขียนว่า "มีรูปในระบบ" แทน
7. **หน้าจอที่เปิดอยู่เปลี่ยนตามทันที:** server ส่ง `settings:update`, `agenda:update`, `prizes:update`, `organization-types:update`, `overview:update`, รายชื่อให้หน้าจอเจ้าหน้าที่ และ `data:reset` `{ event_id, sections }` จอ LED จึงล้างชื่อแขกคนล่าสุดและผู้ได้รางวัลล่าสุด ส่วนหน้าสุ่มรางวัลโหลดข้อมูลใหม่

**ผลกระทบ:**
- ค่าเริ่มต้นของการตั้งค่าอยู่ที่ `DEFAULT_SETTINGS` และ `SETTINGS_GROUPS` (`server/repositories/settingsRepository.js`) เมื่อเพิ่มการตั้งค่าใหม่ ให้ใส่ค่าเริ่มต้นและกลุ่มแท็บที่นั่น แล้วเพิ่มแถวใน `generalRows` / `registrationRows` (Excel)
- ตารางใหม่ที่ผูกกับงาน ต้องเพิ่มในการรีเซ็ต (`server/services/resetService.js`) ในหมวดที่เหมาะสม และในไฟล์สำรอง
- ทดสอบ: `server/tests/reset.test.js` ทำงานบนงานที่สร้างขึ้นเฉพาะเทสต์ ส่วน `client/e2e/backup-reset.spec.ts` รีเซ็ตจริงบนฐานข้อมูลของเครื่อง โดยคัดลอกข้อมูลไว้ใน schema `e2e_snapshot` ก่อน แล้วคืนให้ครบหลังจบ
- ก่อนรีเซ็ตบนเว็บจริง ควรสำรองฐานข้อมูลทั้งก้อนด้วย ([runbook](../runbook.md))
