# 0016-live-updates-and-network-access

จอ LED และหน้าเจ้าหน้าที่ต้องอัปเดตทันทีเมื่อมีการเช็คอิน ไม่ว่าจะเปิดจากเครื่องไหนในวง LAN · การส่งข้อมูลสดจึงเปลี่ยนดังนี้

1. **แท็บละ 1 การเชื่อมต่อ** (`client/src/lib/socket.ts`) ใช้ร่วมกันทุก component (เดิม 3 การเชื่อมต่อต่อแท็บ) · WebSocket ก่อน ถ้าเครือข่ายบล็อกจะใช้ HTTP long-polling แทน (`tryAllTransports`)
2. **รายชื่อผู้เข้าร่วม (ข้อมูลส่วนบุคคล) ส่งเฉพาะหน้าจอเจ้าหน้าที่** หน้าแดชบอร์ดส่ง `staff:join` พร้อม token แล้ว server ใส่ห้อง `staff` (`server/utils/realtime.js`) · เดิม `participants:update` ส่งรายชื่อพร้อมอีเมล เบอร์โทร และรูป ไปทุกหน้าจอรวมผู้ที่ไม่ได้ login (ข้อมูลรั่ว และข้อมูลใหญ่ขึ้นตามจำนวนคน) · ผลการสุ่มรางวัลไม่มีอีเมลอีกต่อไป
3. **ลำดับการส่ง** ตอนเช็คอิน: `welcome:new_checkin` → `overview:update` → รายชื่อ (ถ้ามีหน้าจอเจ้าหน้าที่) · ตัวเลขสรุปนับด้วย SQL `COUNT` ไม่โหลดรายชื่อทั้งหมด
4. **เปิดจากเครื่องอื่นในวง LAN ได้ทันที:**
   - `client/src/lib/apiBase.ts`: ถ้า `NEXT_PUBLIC_API_URL` เป็น `localhost` แต่เปิดหน้าเว็บผ่าน IP (มือถือ/ทีวี/PC จอ LED) จะเรียก API ที่ IP เดียวกันแทน
   - `next.config.ts` `allowedDevOrigins`: โหมดพัฒนา Next.js 16 ปฏิเสธไฟล์ JavaScript (403) เมื่อเปิดผ่าน IP อื่นนอกจาก localhost ทำให้ปุ่มเต็มจอและข้อมูลสดไม่ทำงานบนมือถือ จึงอนุญาตช่วง IP ภายใน (192.168.x.x, 10.x.x.x, 172.x.x.x, *.local) · production ไม่มีข้อจำกัดนี้
5. **จอ LED แบบเต็มจอแสดงป้ายแดง "ขาดการเชื่อมต่อ"** เมื่อการเชื่อมต่อหลุด และโหลดตัวเลขใหม่เมื่อกลับมา · เต็มจอบน iPhone (ไม่มี Fullscreen API) ใช้การคลุมหน้าเบราว์เซอร์แทน

**ผลกระทบ:**
- หน้าจอใหม่ที่ต้องการรายชื่อสด: `useWebSocket({ staff: true })` · หน้าจอสาธารณะ: `useWebSocket()` · สถานะการเชื่อมต่ออย่างเดียว: `useSocketStatus()`
- event ใหม่ที่มีข้อมูลส่วนบุคคลต้องส่งเข้าห้อง `staff` เท่านั้น (ทดสอบใน `server/tests/realtime.test.js` และ `client/e2e/led-realtime.spec.ts`)
- IP ของเครื่องเปลี่ยน (ย้าย Wi-Fi) ต้อง restart `npm run dev` ของ client ถ้าอยู่นอกช่วงที่อนุญาต
