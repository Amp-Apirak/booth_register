# 0012-organization-types

ประเภทองค์กรเก็บในตาราง `organization_types` (ต่องาน) ไม่ใช่ key ใน `settings` · ผู้เข้าร่วมเก็บ `participants.organization_type_id` (FK, `ON DELETE SET NULL`) หรือ `organization_type_other` (ข้อความเมื่อเลือก "อื่นๆ") อย่างใดอย่างหนึ่ง · หน้า `/register` **บังคับเลือก** โดยตรวจที่ server

**เหตุผล:**
1. แต่ละประเภทมีชื่อไทย/อังกฤษ, ลำดับ, สีในกราฟ, เปิด/ปิด และจำนวนผู้เลือก — เป็นข้อมูลเชิงสัมพันธ์ ใช้ FK ให้กราฟนับได้ตรง แม้เปลี่ยนชื่อภายหลัง
2. "อื่นๆ" ไม่ใช่แถวในตาราง: แสดงท้ายสุดเสมอและเก็บข้อความที่ผู้ลงทะเบียนพิมพ์ กราฟรวมเป็นกลุ่ม "อื่นๆ" ส่วนหน้า Dashboard แสดงข้อความจริง
3. ลบประเภทที่มีคนเลือกแล้วไม่ได้ (409 `IN_USE`) ให้ปิด "แสดงในหน้าลงทะเบียน" แทน ข้อมูลเดิมยังอยู่ในรายงาน
4. สีเลือกได้จากชุดสี 8 ช่องที่ตรวจแล้ว (น้ำเงิน, แดง, เขียว, ม่วง, ส้ม, เขียวน้ำทะเล, เหลือง, ชมพู — ตามลำดับนี้) ซึ่งแยกกันออกสำหรับผู้มีภาวะบกพร่องการเห็นสีทั้งธีมมืดและสว่าง · เก็บเป็นชื่อช่อง (`blue` …) ไม่ใช่ hex · สีเทาสงวนไว้ให้ "อื่นๆ" และ "ไม่ระบุ" · ชุดสีแบบ Google Forms ที่ผู้ใช้ส่งมาไม่ผ่านการตรวจ จึงไม่ใช้
5. `database/schema.sql` รันเฉพาะตอนสร้าง volume ครั้งแรก การย้ายข้อมูล (สร้างตาราง, เพิ่มคอลัมน์, ใส่ 6 ประเภทเริ่มต้นเมื่อยังไม่มี) จึงอยู่ใน `organizationTypeRepository.initTable()` ที่รันทุกครั้งที่เปิด server

**ผลกระทบ:**
- ผู้ลงทะเบียนก่อนมีฟีเจอร์นี้เป็น "ไม่ระบุ" เจ้าหน้าที่เลือกแทนได้ในคอลัมน์ของ Dashboard
- เพิ่ม/นำเข้าโดยเจ้าหน้าที่ไม่บังคับประเภท · นำเข้า Excel จับคู่ด้วยรหัสหรือชื่อไทย/อังกฤษ (ไม่สนตัวพิมพ์และช่องว่างรอบ `/`) ไม่ตรง = เก็บเป็น "อื่นๆ: ข้อความ"
- Deploy production ต้อง restart server หนึ่งครั้งเพื่อให้ migration ทำงาน
- ถ้าเปลี่ยนชุดสี ให้แก้ `COLOR_SLOTS` ใน server และ `ORG_COLORS` ใน `client/src/lib/orgTypes.ts` พร้อมกัน และตรวจสีใหม่ก่อนใช้
