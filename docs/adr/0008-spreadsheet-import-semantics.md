# 0008-spreadsheet-import-semantics

การนำเข้า Excel/CSV (ผู้เข้าร่วม, ของรางวัล, กำหนดการ) อ่านไฟล์และแสดงตัวอย่าง/ตรวจสอบที่เบราว์เซอร์ แล้วส่งเป็น JSON ให้ server ซึ่งตรวจซ้ำและบันทึกใน **transaction เดียว**

| ข้อมูล | เมื่อพบรายการเดิม | รายการที่ไม่มีในไฟล์ | endpoint |
|---|---|---|---|
| ผู้เข้าร่วม | อีเมลซ้ำ → ข้าม (รายงานเลขแถว) | ไม่แตะ | `POST /participants/import` |
| ของรางวัล | ตรง `code` แล้ว `name` → อัปเดต (รูปว่าง = คงรูปเดิม) | ไม่ลบ | `POST /prizes/import` |
| กำหนดการ | แทนที่รายการบนหน้าจอทั้งหมด (ยังไม่บันทึกจนกด "บันทึก") | ถูกแทนที่เมื่อบันทึก | `PUT /agenda` (เดิม) |

**เหตุผล:**
1. ผู้ใช้ต้องเห็นว่าแถวไหนมีปัญหาก่อนบันทึก ภาษาไทยและรูปแบบ Excel หลากหลาย การ parse ที่เบราว์เซอร์ด้วย `xlsx` (มีอยู่แล้ว) ให้ preview ทันที
2. ไม่ลบข้อมูลที่ไม่มีในไฟล์ เพื่อไม่ให้ประวัติเช็คอิน/ผู้ได้รับรางวัลหาย (`awarded_count` ผูกกับชื่อรางวัล)
3. ไฟล์ "ส่งออก Excel" ของทุกหน้านำกลับเข้ามาได้ทันที (คอลัมน์เกินถูกละเลย รูปที่อัปโหลดแทนด้วยข้อความ "มีรูปในระบบ"/"จัดเก็บรูปในระบบแล้ว" และคงรูปเดิมเมื่อนำเข้า)
4. รหัสตั๋ว `SER{YYYYMMDD}{4 หลัก}` มีเพียง ~9,000 ค่าต่อวัน การนำเข้าจึงตรวจรหัสที่มีอยู่ก่อนสร้าง

**ผลกระทบ:**
- ตรรกะแปลงคอลัมน์อยู่ใน `client/src/lib/participantImport.ts` และ `prizeImport.ts` (มี unit test ใน `client/tests/`)
- การนำเข้าผู้เข้าร่วม **ไม่ส่งอีเมลตั๋ว** (ป้องกันการยิงอีเมลจำนวนมาก) ถ้าต้องการให้เพิ่มเป็นตัวเลือกภายหลัง
- งานที่ลงทะเบียน/นำเข้าเกินหลักพันคนต่อวันควรขยายความยาวรหัสตั๋ว
