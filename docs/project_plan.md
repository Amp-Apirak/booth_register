## 2. รายละเอียดงานในแต่ละสปรินต์ (Sprint Backlog & Tasks)

### 📌 SPRINT 1: Core Portal & Registration System
*   **เป้าหมายหลัก**: ผู้เข้าร่วมงานสามารถแสกนลงทะเบียนเข้าฐานข้อมูลหลัก และได้รับสติกเกอร์ QR Code ส่งเข้าอีเมล
*   **Backlog Items**:
    1.  **[Task-101] Database Initialization (2 SP)**
        *   *รายละเอียด*: จัดทำ PostgreSQL Instance บนคลาวด์ รันสคริปต์ [schema.sql](../database/schema.sql) และโหลดข้อมูลชุดทดสอบจาก [seed.sql](../database/seed.sql)
        *   *ผู้รับผิดชอบ*: SA / Backend Developer
    2.  **[Task-102] Backend Register API (3 SP)**
        *   *รายละเอียด*: เขียน API endpoint `POST /api/v1/events/:event_id/register` เพื่อรับข้อมูล บันทึก และออกรหัสตั๋วแบบไม่ซ้ำ
        *   *ผู้รับผิดชอบ*: Backend Developer
    3.  **[Task-103] Participant Register Page UI (3 SP)**
        *   *รายละเอียด*: พัฒนาเว็บแบบฟอร์มลงทะเบียนออนไลน์ ปรับให้กระชับและรองรับการเปิดจากมือถือ
        *   *ผู้รับผิดชอบ*: Frontend Developer
    4.  **[Task-104] QR Code Generation & Ticket PDF (5 SP)**
        *   *รายละเอียด*: ระบบสร้างรหัสคิวอาร์เป็นไฟล์ภาพ และจัดทำเทมเพลตส่งตั๋ว Event Pass เข้าอีเมล (SMTP Integration)
        *   *ผู้รับผิดชอบ*: Backend Developer
    5.  **[Task-105] Integration Testing (3 SP)**
        *   *รายละเอียด*: ทดลองกรอกฟอร์ม ➔ เช็คความถูกต้องในฐานข้อมูล ➔ ตรวจสอบไฟล์คิวอาร์ที่ส่งเข้าอีเมล
        *   *ผู้รับผิดชอบ*: QA / Tester

### 📌 SPRINT 2: Check-in Gateway & Real-time Connection

*   **Backlog Items**:

    3.  **[Task-203] WebSocket Server Configuration (5 SP)**

## 3. ดัชนีความเสี่ยงโครงการและวิธีป้องกัน (PM Risks & Mitigation)

1.  **ปัญหาเครือข่ายอินเทอร์เน็ตหน้างานหลุด (Network Outage)**
    *   *ความเสี่ยง*: เครื่องสแกนสตาฟไม่สามารถส่งข้อมูลเข้า API คลาวด์ได้ ทำให้เช็คอินสะดุด
    *   *วิธีป้องกัน*: พัฒนาระบบ Frontend Scanner ให้ทำงานแบบ **Offline Mode (Local Storage Caching)** ดึงข้อมูลสเกนเก็บไว้ในตัวเครื่องชั่วคราว และทำการซิงค์เข้าคลาวด์ทันทีเมื่อสัญญาณอินเทอร์เน็ตกลับมาทำงานปกติ
2.  **เครื่องยิงสแกนเนอร์ส่งข้อมูลผิดรูปแบบ**
    *   *ความเสี่ยง*: เครื่องยิงส่งค่า String เพี้ยนหรือมีตัวอักษรพิเศษส่งผลต่อระบบค้นหา
    *   *วิธีป้องกัน*: จัดฟังก์ชันครอบ input ทำความสะอาดข้อมูล (Data Sanitization) ตัดช่องว่างหรืออักขระพิเศษทิ้งก่อนส่งยิง API
3.  **ปัญหาจอแสดงผลต้อนรับกระตุกหรือทำงานไม่ทัน**
    *   *ความเสี่ยง*: สตาฟแสกนเร็วมากจนจอ LED ส่วนกลางเปลี่ยนรายชื่อต้อนรับไม่ทันเกิดอาการสับสน
    *   *วิธีป้องกัน*: ออกแบบระบบจัดการคิวข้อความต้อนรับ (Welcome Message Queue) ฝั่งหน้าบ้าน โดยหน่วงเวลาแสดงรายชื่อละอย่างน้อย 3-4 วินาทีและค้างข้อมูลเรียงลำดับในคิวไว้แสดงผลอย่างเป็นระบบ
